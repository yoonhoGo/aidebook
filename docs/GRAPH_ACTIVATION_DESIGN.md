# 3D 지식 그래프와 AI 참조 활성화 설계

작성: 2026-09-19

상태: 2026-09-19 설계 기록. 2026-09-21 그래프 UI와 fixture 재생을 현재 앱에 통합했다. 실제 Core/agent 추적 연동은 후속 범위다. 최신 검증은 [통합 검토 기록](GRAPH_UI_INTEGRATION.md)을 따른다.

## 목적과 컨셉

컨셉은 **Evidence Constellation — AI가 참조하는 근거의 별자리**다. 문서, 사용자 메모와 관계를 3D 공간에서 탐색하고, 특정 요청에서 어떤 자료가 반환되거나 답변에 인용됐는지 확인한다.

기존 Aidebook의 밝은 문서 UI와 오른쪽 Evidence Inspector를 유지하면서 중앙에 짙은 잉크색 그래프 캔버스를 추가한다. 현재 작업 주변의 그래프를 기본으로 보여주고, 관측된 요청 이벤트에 따라 해당 노드와 연결을 강조한다.

설계의 중심은 활성화의 의미다. 그래프는 관측 가능한 자료 접근·반환·인용을 표현한다. 모델 내부의 사고 과정이나 실제 인과관계를 보여준다고 설명하지 않는다.

## 현재 구현과 연결되는 경계

- 프런트엔드는 React·TypeScript, 데스크톱 호스트는 Tauri 2, 저장소는 Rust Core가 소유하는 SQLite·FTS5다.
- 현재 `context.search`는 검색 결과를, `context.get`은 자료·메모·접근 불가 자료·freshness·충돌 정보를 반환한다.
- 현재 응답만으로는 자료가 모델 프롬프트에 포함됐는지, 답변에 실제 사용됐는지 판정할 수 없다.
- 기존 source relation과 memory evidence를 유지한다. 코드·문서에서 추출한 파생 관계는 별도 계층으로 관리한다.
- 후보 메모의 검토·승인, revision, 철회·복원 규칙을 유지한다.

## 활성화 상태의 의미

| 상태 | 의미와 확인 조건 | 시각 표현 |
| --- | --- | --- |
| 검색 결과 포함 | Core 검색 결과에 해당 ID가 포함됨 | 약한 외곽선 |
| 에이전트에 반환 | transport에서 해당 자료의 반환을 관측함 | 짧은 빛 이동 |
| 컨텍스트 포함 | 에이전트 연동이 실제 프롬프트 포함을 보고함 | 별도의 포함 배지 |
| 답변에 인용 | 답변의 명시적 인용과 자료 ID를 연결할 수 있음 | 지속 강조와 인용 번호 |

관측이 없는 단계는 미확인으로 표시한다. Core에서 응답을 만들었다는 사실과 클라이언트가 수신했다는 사실도 구분한다. 수신 확인이 없다면 문구를 `반환 응답 생성` 등 실제 관측 범위에 맞춘다.

답변 인용은 모델이 생성한 인용이라는 출처를 보존한다. 인용이 존재한다고 내용의 정확성이나 모델 내부 사용 경로가 검증된 것은 아니다. 각 이벤트에는 관측 주체를 남겨 Core 관측과 에이전트 보고를 구분한다.

## 지식 관계와 요청 경로

영속 그래프는 문서 간 명시적 관계, 메모의 근거, 파생 코드·문서 관계를 표현한다. 요청 경로는 선택한 요청에서 관측된 접근·전달·인용 이벤트를 표현한다. 요청 경로는 기본 그래프 위에 일시적으로 겹쳐 표시하고 재생할 수 있게 한다.

- 양끝 노드가 활성화됐다는 이유로 사이의 모든 연결을 강조하지 않는다.
- 관계 탐색을 실제 관측했을 때만 해당 관계에 이동 효과를 적용한다.
- 자료가 직접 반환됐다면 자료에서 임시 요청 노드로 이어지는 전달 연결을 사용한다. 임의의 중간 메모를 거치는 경로를 만들지 않는다.
- 전달 연결과 지식 관계는 선 스타일·범례로 구분한다.
- AI를 표현하는 큰 노드는 현재 요청을 나타내는 임시 노드로 사용한다.
- 동시 요청은 요청 선택기로 구분하고 기본 화면에는 선택한 요청의 경로를 표시한다.

## 화면과 상호작용

기존 탐색 메뉴에 `그래프`를 추가한다. 중앙 그래프와 오른쪽 근거 패널을 함께 사용한다.

- 기본 범위: 현재 Work의 관련 노드와 1~2단계 이웃.
- 상단: 요청 선택기, 현재 관측 상태, 자료 수, 실시간·재생 모드.
- 필터: 자료 종류, 관계 종류, freshness, 활성 자료만 보기, 탐색 깊이.
- 노드 선택: 제목, 원문 발췌, 자료 종류, 반환한 버전, 수집 시각, 표시 이유를 근거 패널에 표시.
- 인용 선택: 답변의 인용 위치와 해당 근거를 연결.
- 연결 선택: 관계 종류, 추출·추론 여부, 근거 위치를 표시.
- 카메라: 사용자 조작으로 회전·확대·이동. 자동 회전은 기본으로 사용하지 않음.
- 2D 보기: 노드 ID와 선택 상태를 유지하면서 깊이를 접어 읽기 쉬운 배치를 제공.
- 접근성: 키보드로 사용할 수 있는 자료·관계 목록을 함께 제공.

## 시각 규칙

| 요소 | 표현 |
| --- | --- |
| Source | 문서 마커, 낮은 채도의 회청색 |
| 승인된 Memory | 원형 노드 |
| Candidate | 다이아몬드 마커와 후보 배지 |
| 현재 요청 | 구형 또는 육각형 임시 노드 |
| 일반 관계 | 얇고 낮은 불투명도의 선 |
| 활성 노드 | 밝은 중심과 절제된 시안색 외곽광 |
| 관측된 전달 | 방향성 파티클과 전달 범례 |
| 명시·추출 관계 | 실선, 상세 패널에 provenance 표시 |
| 추론 관계 | 점선, 추론 배지 |
| 오래된 자료·접근 불가 | 상태 아이콘과 텍스트 |

색상만으로 상태를 구분하지 않는다. 선택·활성 노드의 제목과 종류는 읽을 수 있어야 한다. 밝기는 선택·활성 상태에만 대응하며 신뢰도를 암시하지 않는다. 후보 상태와 활성 상태는 독립적으로 표현한다.

## 애니메이션 규칙

1. 평상시에는 위치가 안정된 그래프를 표시한다.
2. 실제 이벤트가 도착하면 해당 노드와 관측된 연결을 강조한다.
3. 병렬 이벤트는 병렬로 표시한다. 순차 탐색을 관측하지 않았다면 설명을 위해 임의의 순차 경로를 만들지 않는다.
4. 노드 펄스는 초기 시안으로 600~900ms 범위를 검토한다. 이는 데이터 처리 시간이 아닌 시각 효과 시간이다.
5. 완료 후 이동 효과를 멈추고 선택한 요청의 강조를 유지한다.
6. 재생 속도를 조절하는 경우 `재생 모드`와 원래 이벤트 시각을 표시한다.
7. `reduceMotion` 또는 OS 동작 줄이기 설정에서는 파티클과 펄스를 생략하고 외곽선·배지로 상태를 표현한다.

활성화 동안 노드 위치를 다시 계산해 화면이 흔들리지 않도록 한다. 레이아웃 변화와 이벤트 강조는 독립적으로 처리한다.

## 데이터와 이벤트 모델 제안

`activeNodeIds`와 `activeEdgeIds`는 이벤트에서 계산하는 화면 상태다. 이 배열만 저장하면 활성화 이유와 시간을 설명하거나 재생하기 어렵다.

```ts
type ReferenceStage =
  | "search_result"
  | "response_prepared"
  | "delivery_confirmed"
  | "context_included"
  | "answer_cited";

type ReferenceEvent = {
  eventId: string;
  requestId: string;
  sequence: number;
  stage: ReferenceStage;
  observer: "core" | "transport" | "agent";
  nodeIds: string[];
  edgeIds: string[]; // 실제 관측된 관계만 포함
  references: Array<{
    nodeId: string;
    snapshotId?: string;
    contentHash?: string;
    memoryVersion?: number;
  }>;
  occurredAt: string;
  recordedAt: string;
  answerId?: string;
  citationIds?: string[];
};
```

이 타입은 구현 전 검토용 초안이다. 실제 계약에서는 단계별 필수 필드를 구분한 타입으로 잘못된 조합을 거부한다. source에는 snapshot/hash, memory에는 revision을 연결해 과거 요청이 읽은 자료를 현재 자료와 구분한다.

- 요청 내 sequence로 순서를 정하고 eventId로 중복을 제거한다.
- 에이전트와 Core의 시계 차이를 고려해 관측 시각과 기록 시각을 분리한다.
- 누락된 이벤트나 재연결 구간은 미확인으로 표시한다.
- 재생에는 해당 시점의 관계·자료 버전을 사용한다. 보존되지 않은 본문을 현재 내용으로 대체해 과거 근거로 표시하지 않는다.
- 이벤트는 ID·버전·상태 중심으로 저장한다. 원문·프롬프트의 추가 보존과 보존 기간은 별도 정책으로 정한다.
- 구독과 재생 조회는 기존 IPC 의미를 변경하지 않는 버전 있는 새 계약으로 설계한다. 현재 IPC에 스트리밍이 구현돼 있다고 가정하지 않는다.

## 렌더링 기술 제안

초기 구현 후보는 `react-force-graph-3d`와 `three`다. 커스텀 노드, 방향성 파티클과 카메라 제어를 활용한다. 그래프 데이터와 이벤트는 렌더러에서 분리해 2D 보기와 목록 보기에서도 같은 상태를 사용한다.

그래프 조회와 요청 기록은 기존 단일 Core owner 경계를 따른다. UI·CLI·MCP가 SQLite를 직접 열지 않는다. 외부 그래프 DB는 초기 필수 의존성으로 추가하지 않는다.

앞서 제안한 노드 150~200개, 활성 연결 12개는 검증된 제한이 아닌 시안의 가정이다. 활성 근거를 개수 제한 때문에 숨기지 않는다. 주변 노드 묶기, 라벨 밀도 조절, 단계적 확장으로 복잡도를 낮추고 대상 macOS WebView에서 성능을 측정한다. 발광 효과는 측정 결과에 따라 줄일 수 있게 한다.

## 구현 순서

1. **탐색 그래프:** 현재 자료·메모·명시적 관계를 표시하고 선택 시 기존 근거 패널을 연결한다. 데모 데이터를 사용하면 화면에 표시한다.
2. **Core 요청 기록:** 검색 결과와 응답 생성 이벤트를 기록하고 실제 관측에 따라 활성화한다. UI·CLI·MCP 진입점이 같은 기록 경계를 사용한다.
3. **에이전트 연동:** 수신 확인, 프롬프트 포함과 답변 인용을 보고하는 계약을 추가한다. 지원하지 않는 클라이언트는 해당 단계를 미확인으로 둔다.
4. **재생과 비교:** 요청별 타임라인, 재연결 복구, 과거 자료 버전과 현재 자료 차이를 제공한다.

## 검증 기준

- 검색 결과 포함만으로 `답변에 사용됨` 또는 `인용됨`을 표시하지 않는다.
- 실제 반환 자료와 화면의 활성 자료 ID·버전이 일치한다.
- 활성 노드 사이의 관측되지 않은 연결이 자동으로 켜지지 않는다.
- 병렬·중복·지연·누락 이벤트와 동시 요청이 서로의 상태를 오염시키지 않는다.
- 같은 기록을 재생하면 같은 활성 상태와 순서가 나온다.
- 오래된 자료, 접근 불가, 충돌과 후보 상태가 활성 효과 때문에 사라지지 않는다.
- 키보드·목록 보기·동작 줄이기에서도 같은 근거에 접근할 수 있다.
- 그래프의 위치 안정성과 선택 유지, 실제 macOS WebView의 성능을 확인한다.

정적 목업, 브라우저 데모, fixture 검증과 native/live 에이전트 연동 검증은 각각 구분해 기록한다.
