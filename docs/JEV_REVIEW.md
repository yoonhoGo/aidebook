# Jev 도입 검토

저장: 2026-09-21. 조사 기준: 2026-09-20 공식 문서와 당시 Aidebook 코드.
상태: 최후순위 검토 후보. 도입·구현·API 실험은 확정하지 않았다.

## 결론

TypeSafe AI의 Jev는 검색 결과 재정렬과 메모 재검토 후보 선별에 적용할
여지가 있다. 기존 로컬 기능을 유지하는 선택적 판단 기능으로 검토한다.
기존 로드맵과 후속 범위를 먼저 진행하고, 실제 필요가 확인되면 작은
평가부터 수행한다.

Jev는 입력 자료와 질문을 받아 Choice(선택), Score(기준별 점수),
Noul(명제가 참일 확률)을 반환한다. 여러 질문을 같은 입력에 대해 한 번에
평가할 수 있지만 자유로운 메모 본문이나 요약을 작성하지는 않는다.

## 적용 후보

| 후보 | 현재 기반 | 기대 효과 | 우선순위 |
|---|---|---|---|
| 검색 결과 재정렬 | SQLite FTS5·BM25 검색 | 질문에 직접 답하는 자료를 상위에 배치 | 검토 착수 시 첫 실험 |
| 메모 재검토 후보 | 근거·revision·최신성 관리 | 원본 변경이 기존 주장에 영향을 주는지 선별 | 검색 실험 이후 |
| 메모 유형 추천 | claim_type과 근거 저장 | 결정·선호·제약·미해결 질문 등 추천 | 보조 기능 |
| 자료 관계 추천 | 명시적 SourceRef 링크 | 관련 자료 후보 제시 후 사용자 확인 | 후순위 |

### 검색 결과 재정렬

`src-tauri/src/core/db.rs`의 검색은 FTS5 후보를 BM25로 정렬한다.
로컬 검색 상위 20개 자료를 대상으로 관련성을 평가하고 결과 순서를
조정하는 방식을 실험할 수 있다. 예를 들어 GitHub 언급이 많은 문서보다
GitHub 읽기 전용 범위를 결정한 기록을 질문에 맞게 우선 표시한다.

최초 검색에서 누락된 자료는 재정렬만으로 복구할 수 없다. 한국어 검색의
후보 누락과 재정렬 품질은 별도로 평가한다.

### 메모 재검토 후보

조사 당시 `ContextResponse.conflicts`는 빈 배열로 반환되고 있었다.
원본 변경 시 기존 메모와 변경 내용을 비교해 다음 질문을 평가할 수 있다.

- 새 자료가 기존 메모의 주장과 충돌하는가?
- 기존 결정의 취소를 명시하는 근거가 있는가?
- 판단에 필요한 정보가 부족한가?

결과는 재검토 권장 표시와 원문 비교에 사용한다. 수집 시각 기반 `stale`과
의미상 충돌을 구분하고 메모 수정·철회는 사용자가 결정한다.

## 제약과 도입 조건

- 출력 스키마 보장은 판단 내용의 정확성을 보장하지 않는다. 권한 승인,
  자동 병합, 메모 자동 철회의 근거로 사용하지 않는다.
- Choice·Score의 `confidence`는 확률 분포에서 계산한 값이다.
  `0.9`를 정확도 90%로 간주하지 않고 실제 평가 자료로 임계값을 정한다.
- 공식 문서는 영어 성능이 가장 좋으며 CJK 언어의 성능이 동일하지 않다고
  명시한다. 한국어와 한영 혼합 자료로 평가해야 한다.
- 로컬 자료의 외부 API 전송에는 별도 선택 설정과 전송 범위가 필요하다.
  고객 데이터 학습 미사용과 무보관은 다르며, 조사 당시 공식 문서는
  ZDR을 기업 고객 항목으로 안내했다. 착수 시 실제 이용 경로의 조건을 재확인한다.
- 조사 당시 공식 가격은 입력 100만 토큰당 $0.042, 출력 무료였다.
  요청 전체 5,000토큰 기준 1만 회는 약 $2.10이다. 가격·모델·제공 조건은
  재확인이 필요하며, 네트워크 지연과 운영 비용을 별도로 측정한다.
- 현재 교체할 모델 호출이 없으므로 비용 절감보다 기능 개선 효과를 평가한다.

## 도입을 검토할 때의 구성안

Rust Core에 선택적 판단 어댑터를 두고 모델 버전·질문 버전·입력 해시와
평가 결과를 기록한다. 접근 가능한 자료 중 필요한 부분만 보내며,
API 장애나 낮은 확신에서는 기존 로컬 검색 결과를 사용한다.
검색·저장·오프라인 사용에 Jev를 필수 의존성으로 두지 않는다.
기존 근거·버전 충돌·사용자 검토 계약은 유지한다.

## 검토 완료 기준

1. 기존 로드맵과 후속 범위 이후에도 해결할 검색·재검토 문제가 있는지 확인한다.
2. 전송 가능한 한국어·한영 혼합 질문 50~100개와 관련 자료 정답을 준비한다.
3. 기존 FTS5 검색과 Jev 재정렬의 상위 5개 유용성, 후보 누락,
   응답 지연, 호출 비용을 비교한다.
4. 장애·낮은 확신에서 로컬 기능 유지 여부와 데이터 처리 조건을 확인한다.
5. 결과에 따라 도입·보류·미도입을 기록한다. 도입 결정 이후에만 구현 범위를 정한다.

조사는 공식 문서와 코드 검토까지 수행했다. 실제 Jev API 호출, 사용자
자료 전송, 정확도·속도 측정, 코드 구현은 수행하지 않았다.
